# 택시팟 프론트엔드

성북구 택시 합승 서비스의 Next.js App Router 프론트엔드입니다. 루트 PRD의 Phase 1-A~1-H 화면과 체험 흐름을 구현했습니다. 모든 변경은 `frontend/` 안에 있습니다.

## 실행

앱과 테스트 도구를 함께 사용하려면 Node.js 22.12 이상이 필요합니다. 이 작업은 Node.js 24.21.0 / Windows에서 검증했으며 `.nvmrc`는 24로 지정했습니다. Next.js 자체의 최소 버전(20.9)만으로는 설치된 테스트 도구의 요구사항을 충족하지 못합니다.

```powershell
cd C:\codex.btbr\newbiethon\frontend
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:3000 을 엽니다. Vercel에서는 Root Directory를 `frontend`로 지정하면 됩니다. 아직 배포하지 않았습니다.

## 구현한 화면

- 팟 찾기: 출발/도착 역 검색, 성별/잔여석 필터, 최신순·출발순·현재 위치 거리순 정렬, 위치 거부 시 최신순, 빈 결과 안내.
- Google 로그인 진입 및 체험 로그인, 최초 프로필 입력, 마이페이지에서 이름·성별·계좌 수정.
- 팟 생성: 고정 역 목록, 미래 출발시간, 2~4명 모집/최소인원, 예상가격 검증, 호스트 등록 성별 자동 적용.
- 팟 상세: 참가/탈퇴, 정원 및 성별 제한, 호스트 탈퇴 시 폐지, 참가자/투표 현황.
- 마일리지: 피크닉 쿠폰 반복 충전, 계좌 송금 체험 충전, 잔액 및 부족 안내.
- 전원 동의 시 확정 및 포인트 보관, 확정 후 탈퇴 제한, 호스트 정산, 완료/폐지 이력.
- 출발시간 도달 시 30분 연장 팝업, 전원 동의/거절 흐름. 닫아도 내 팟 상세에서 다시 투표할 수 있습니다.
- 휴대폰 하단 메뉴, 키보드 포커스, 팝업 안에서 Tab/Shift+Tab 순환 및 Escape 닫기, 상태/오류 알림.

## 체험하는 방법

1. 로그인 → **체험 계정으로 시작하기**를 선택합니다.
2. 예시 이름, 성별, 은행, 6~20자리 예시 계좌번호를 입력합니다. 실제 개인정보는 사용하지 마세요.
3. `피크닉` 쿠폰으로 50,000 P를 충전합니다.
4. 팟에 참가하거나 직접 만듭니다. 직접 만든 팟에서는 **체험: 참가자 1명 추가**로 동행을 재현합니다.
5. 본인이 확정에 동의하고 **체험: 다른 참가자 확정 동의**를 눌러 전원 동의를 재현합니다.
6. 직접 만든 팟에서는 도착 완료·정산 버튼을 누른 뒤 **내 팟 → 이용 이력**을 확인합니다.

체험 동의 버튼은 명시적으로 누를 때만 예시 참가자의 상태를 변경합니다. 실제 이용자의 동의를 대신하지 않습니다.

## 현재 한계와 백엔드 연결

저장소의 `docs/api-contract.md`에는 아직 실제 요청/응답 계약이 없습니다. 따라서 임의의 API를 만들거나 호출하지 않았으며 백엔드 코드를 변경하지 않았습니다. `lib/demo.ts`는 **클라이언트 체험 모델**로, 서버 모델이나 보안 검증을 대신하지 않습니다.

- 데이터는 브라우저 메모리에만 있으며 새로고침/로그아웃 시 초기화됩니다. 계좌, 위치, 토큰을 localStorage에 저장하지 않습니다. 서버 저장·다른 기기 간 동기화는 미구현입니다.
- 역 8개와 좌표는 화면/거리 정렬을 확인하기 위한 예시입니다. 공공데이터에서 수집한 전체 성북구 정류장 데이터가 아닙니다.
- 연장 감지는 화면이 열린 동안 동작합니다. 실제 서비스는 서버의 시간 및 전원 투표 상태가 기준이어야 합니다.
- 실제 다중 사용자 합승, 프로필 영구 저장, 서버 권한 검증, 원자적 포인트 보관/정산은 백엔드 연결 전에는 사용할 수 없습니다.
- 서버 계약 확정 후 인증 토큰 전달, 프로필 조회/생성/수정, 정류장/팟/잔액/이력 조회, 참가/탈퇴/투표/정산 요청과 상태 재조회 또는 구독을 연결해야 합니다. 체험 모델의 타입을 서버에 그대로 강제하지 마세요.
- 완료 단계를 기록하는 루트 `PHASE_PLAN.md`는 프론트/백엔드 통합 검증 전이므로 변경하지 않았습니다.

## Google 로그인 설정

`.env.example`을 `.env.local`로 복사하고 Firebase 웹 앱 설정 4개를 입력한 후 개발 서버를 다시 시작합니다. Firebase Authentication에서 Google 제공자를 활성화하고 개발/배포 도메인을 승인된 도메인에 추가합니다.

설정이 없으면 Google 버튼이 비활성화되고 체험 로그인은 그대로 사용할 수 있습니다. `lib/firebase.ts`의 Google 로그인은 실제 Firebase 팝업 인증을 사용합니다. 인증 이후에도 서버 연결 전까지 서비스 데이터는 체험 모드입니다. 실제 Firebase 프로젝트 설정이 제공되지 않아 실제 계정 로그인은 검증하지 않았습니다.

참고: [Next.js 설치 문서](https://nextjs.org/docs/app/getting-started/installation), [Firebase Google 로그인 문서](https://firebase.google.com/docs/auth/web/google-signin).

## 검사

```powershell
npm run typecheck
npm test
npm run build
npx playwright install chromium firefox webkit
npm run test:e2e
```

단위 테스트는 참가 제한, 잘못된 생성 값, 잔액 부족, 전원 투표/정산, 중복 차감 방지, 폐지/연장을 검사합니다. 브라우저 테스트는 배포용 빌드를 포트 3100에서 자동 실행합니다. 따라서 소스 변경 후에는 `npm run build`를 먼저 실행해야 합니다.

Chromium·Firefox·WebKit 데스크톱, Chromium Android 화면, WebKit iPhone 화면 설정에서 검색·가입·충전·생성·정산·이력·프로필·키보드 이동·연장·위치 정렬·가로 넘침을 검사합니다. 휴대폰 설정 검사는 실물 기기 검사가 아닙니다. Google 인증, Firestore와 실제 API는 검사 대상에 포함하지 않습니다.

초기 로딩 측정은 동일한 데스크톱 Chromium 설정에서만 실행하고 나머지 프로젝트에서는 건너뜁니다. 성능 합격선을 판정하는 테스트가 아닌 측정 기록입니다. 결과는 테스트 첨부 `initial-load.json`과 실행 로그에 남습니다.

요구사항별 충족 상태와 성능·호환성 검사의 한계는 [검토 보고서](./AUDIT.md)에 정리했습니다.

서체는 Google Fonts의 Noto Sans KR를 사용하며, 외부 서체 연결이 안 되면 시스템 글꼴로 표시합니다.
